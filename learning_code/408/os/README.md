## 作答形式

- 只写 PV 伪代码，使用 `P(S)`、`V(S)`；不写 C++，不使用线程库、锁库、管程或条件变量代替信号量。
- P、V 操作本身原子执行；P 在资源／事件不可用时阻塞，不允许忙等或直接读取信号量的内部数值来作判断。
- 可以使用顺序、分支、循环、普通共享变量和信号量数组。共享普通变量若可能并发读写，必须说明保护方式。
- 业务动作可以直接写成“放入一件产品”“修改数据”等，不要求实现缓冲区、链表或队列。
- 各题信号量与普通变量分别声明，列出含义与初值；循环体中的临时数据默认为进程私有。
- 明确区分互斥、资源计数和事件通知；通过执行顺序说明同步要求得以满足。
- 所有业务动作都在有限时间内完成，讨论活性时假定就绪进程最终能得到执行。除题目另有要求，不要求证明无饥饿，不假定信号量一定按 FIFO 唤醒。
- 不把整个业务过程放进一个全局互斥区来规避设计。题目不要求算法时间复杂度，重点是安全性、同步关系、死锁分析与允许的并发。

可采用下面的空白作答格式；这里不预设信号量数量或初值：

```text
共享信号量：
    名称、初值、含义

共享普通变量（如需）：
    名称、初值、保护方式

进程／线程：
    按题目顺序填写业务动作
    在适当位置插入 P(...)、V(...)

说明：
    同步与互斥关系
    关键 P 操作的先后次序
    题目要求的边界情形与死锁分析
```
